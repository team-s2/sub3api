# GitHub 组织白名单

在管理端「系统设置 → 安全设置 → GitHub」中启用组织成员限制，并填写组织登录名，支持逗号、空格和换行分隔。账号属于任一所列组织的正式成员即可通过；开启限制且名单为空时拒绝所有 GitHub 登录。

OAuth 会申请 `read:org` 权限。已有用户需要重新授权；启用第三方应用访问限制的组织需要批准对应的 OAuth App。组织查询失败时拒绝此次登录。

规则覆盖 GitHub 登录及身份绑定。开启限制后，组织成员首次登录即自动开通账号（不走邮箱密码补全，不受注册开关、邀请码、邮箱后缀策略影响），后续登录按 GitHub 数字 ID 找回同一账号，且每次登录都确保其为管理员。成员验证结果绑定 GitHub 数字 ID 和当前规则，在服务端登录流程中有效期为十分钟；规则发生变化后需要重新进行 GitHub 授权。

移除组织成员或修改规则后，现有平台会话及 API Key 仍按各自生命周期生效；即时撤销访问权时，应同时禁用用户并撤销其会话与 Key。

管理设置 API 的 `github_oauth_org_whitelist` 字段：

```json
{"enabled":true,"organizations":["team-s2"]}
```

## 与 team-s2/new-api 的行为对照

| 行为 | Sub3API 当前实现 | new-api fork |
| --- | --- | --- |
| 组织准入 | 任一允许组织的 active 成员可通过 | 任一允许组织的正式成员可通过 |
| 空名单、查询失败 | 拒绝 GitHub 登录 | 拒绝 GitHub 登录 |
| 个人白名单 | 当前准入配置只包含组织 | 支持永久数字用户 ID 兜底准入 |
| 初次注册 | 组织成员登录时自动开通，不受注册、邀请码设置影响 | 沿用 new-api 注册流程 |
| 角色 | 组织成员每次登录都提升为 `admin` | 可自动提升为管理员或超级管理员，在完成所有登录因素后生效 |
| GitHub 登录的二次认证 | 原生邮箱 OAuth 登录路径直接签发 token；现有 2FA 绑定流程使用组织检查结果 | 登录要求按用户配置完成 TOTP 或 Passkey；角色提升在全部因素完成后生效 |
| 组织变动后已有访问 | 平台会话、API Key 按各自生命周期生效 | 需另行撤销会话、令牌和角色 |

未开启限制时 GitHub 登录保持上游的注册补全流程。数字用户 ID 兜底名单及 new-api 的 MFA 后提升语义属于独立能力。
